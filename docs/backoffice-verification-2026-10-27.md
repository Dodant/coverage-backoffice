# 백오피스 실데이터 검증 — 2026-10-27

로컬 기존 PostgreSQL·Redis·Elasticsearch·Kafka·S3(RustFS)를 기동하고 실제 API와 브라우저를 연결해 검증했다. 브라우저 응답을 모킹하지 않았다. 저장 검증은 제목에 `[검증용] 관계·이미지`를 붙인 별도 도서 3권으로 수행했다. 기존 계정의 권한·비밀번호와 기존 도서의 서지정보·연결 관계는 바꾸지 않았다.

## 기존 데이터 조회

기동 직후 원서 142권, 번역서 43권, 표지 245개가 있었다. 총 185권의 전체 상태 목록과 개별 상세를 모두 조회했다. 목록에서 ID 중복·누락이 없었고, 상세 오류도 없었다. 보완 항목 10종의 서버 필터 결과 개수는 각 도서의 보완 표시와 일치했다.

## 저장과 관계 검증

- 관리자 로그인 API로 인증한 실제 세션에서 목록·보완 필터·상세 편집을 사용했다.
- 서지정보와 표지의 종류·시작 쇄·사용 시작일·띠지·출처를 저장하고 다시 조회했다.
- 번역서를 다른 원서로 옮긴 뒤 표지 ID가 유지되고 이전/새 원서의 번역서 목록이 갱신되는지 확인했다.
- 같은 작품의 다른 판으로 연결·분리했으며 번역서가 해당 원서를 계속 따르는지 확인했다.
- 검토 시점과 현재 연결이 다른 요청은 거절되는지 확인했다.
- 실제 저장 파일을 서로 다른 URL로 두 번 업로드하고 SHA-256 동일 파일 결과에 나타나는지 확인했다.
- 대표 표지를 바꾸고 원래 표지로 되돌렸다.
- 실제 브라우저에서 관계 변경의 영향 미리보기·적용·작품 분리·번역서 이동·동일 이미지 결과를 확인했다. 390px 모바일 화면의 가로 넘침과 페이지 예외가 없었다.

## 발견하고 수정한 오류

사용 시작일이 있는 표지에서 대표 표지를 바꾸면 감사 로그의 기본 ObjectMapper가 LocalDate를 직렬화하지 못해 변경이 실패했다. 표지 스냅샷에서 날짜를 ISO 문자열로 기록하도록 수정했다. 같은 조건의 회귀 테스트와 실제 API 재검증을 통과했다.

## 이미지 분석에서 드러난 기존 자료 상태

검증 도서를 포함한 비교 대상 표지 참조 214개를 분석했다. 새 해시 기록 14개를 만들었고, 실패 참조는 195개였다. 실패는 고유 주소 12개에 집중됐다. 최종 원인별 참조 수는 원본 없음 109건, 관리 범위 밖 주소 85건, 빈 파일 1건이다.

| 원인 | 고유 주소 수 | 확인 방법 |
|---|---:|---|
| 관리 저장소 밖의 테스트 주소 | 2 | URL 확인. 임의 외부 URL 다운로드는 수행하지 않음 |
| 원본 파일 없음 | 9 | 관리 저장소 HTTP 404 |
| 빈 원본 파일 | 1 | 관리 저장소 HTTP 200, 본문 0바이트 |

같은 주소가 여러 표지에 사용돼 실패 참조 수가 고유 주소 수보다 크다. 없는 원본은 해시로 비교할 수 없다. 분석 화면에는 원인별 메시지와 해당 도서로 가는 링크를 제공한다. 다른 파일의 분석은 계속 진행한다. 이 작업에서 없는 원본을 임의 이미지로 대체하지 않았다.

## 이미지 판정 범위

파일 SHA-256 일치는 동일 파일 결과다. URL 일치는 같은 저장 주소임을 뜻한다. 유사 이미지는 64비트 dHash 거리 6 이하와 종횡비 차이 3% 이하 조건으로 제시하는 검토 후보다. 유사 후보를 동일 이미지로 확정하거나 자동 병합·삭제하지 않는다. 숨김·삭제·차단 표지는 비교 대상에서 제외한다.

## 자동 검증

프런트엔드 빌드·린트, 커버 에이전트 23개 테스트, 백엔드 168개 테스트 및 패키징을 통과했다. 관계 변경·충돌·공개 상태 제약, 이미지 해시·재압축/리사이즈 후보·숨김 제외, 파일별 분석 실패 격리와 날짜 직렬화 회귀를 포함한다.

## 검증 자료 정리

검증용 원서 2권과 번역서 1권은 API로 삭제 상태로 바꾸고 공개 조회에서 404로 제외되는지 확인했다. 기존 설계에 따라 레코드와 감사 이력은 남는다. 검증 도서 관련 이미지 비교 결과도 0쌍으로 제외됐다. 기존 185권의 서지정보·도서 관계는 보존했다. 구형 이미지에 새로 계산한 해시 메타데이터는 유지했다.
